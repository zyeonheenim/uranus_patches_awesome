# 模块 3 · 入站看门狗（能发不能收 → 自动重连）

## 解决什么

Uranus 有时会出现「半死」状态：**发消息正常**（对方看到已送达），但**收消息彻底断**——
控制台一条新消息都不进来，`/api/health` 却还是 200，界面全绿，看不出来。
常见诱因是电脑睡眠、网络切换、代理抖动后，负责收消息的长连接悄悄断了却没重建。

这个补丁每 60 秒巡检一次，发现收消息通道断了就自动重连，并把过程写进日志。

## 适配范围

- ✅ 从**原版 Uranus** 直接安装（服务端小补丁用官方锚点，已验证原版可命中）
- ✅ macOS（用 launchd 定时 + `pmset`，全是系统自带命令）
- ⚠️ 需要 Uranus 由 launchd 托管，服务名 `com.uranus.imessage`（官方安装方式就是它）

## 装

把本文件夹放进任意位置，双击 `安装.command`。脚本会：

1. 自动找 `~/Uranus_Imessage`（装在别处可设 `URANUS_ROOT` 环境变量）
2. 备份 `server/src/index.js`
3. 给服务端加一个**只收本机回环、只写一行日志**的通知端点
4. 装定时巡检脚本（路径自动替换成你的实际安装位置，无硬编码）
5. 注册每 60 秒的 launchd 任务、重启 Uranus

装完日志在 `Uranus_Imessage/watchdog.log`。平时空着＝正常；真修过才会写一行：
```
YYYY-MM-DD HH:MM:SS 检测到入站订阅异常（连续 3 次），开始自救
```

想看实时状态：网页左下角日志抽屉里找 `[看门狗]` 开头的行（需要本合集的模块 1）。

## 撤销

双击 `卸载还原.command`：停定时任务、还原服务端文件、重启 Uranus。不动你的角色和数据。

## 原理（可选读）

判据只看日志、不需要登录态：比较「最后一次桥接已连接」和「最后一次订阅失败」谁在后。
失败在后＝连上后又崩了；连续 3 次巡检都这样才动手。动作是「先重启桥接（代价小），
25 秒后还不行再重启整个进程」，两次动手之间至少隔 10 分钟防抖。
每 5 分钟级的冷静期设计，刻意避开了早年被验证会死循环的「代理不通就 pkill 重拨」方案。
