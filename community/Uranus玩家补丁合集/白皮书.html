五个补丁，
让你的 Uranus 更稳、更好用。

这是一份写给玩家的说明书。每个补丁讲清三件事：它解决什么痛点、装了之后界面变成什么样、怎么装怎么用。想深入的话，每一节末尾还折叠着原理与兼容性。

✓ 原版可直接装 ✓ 可单独卸载 ✓ 零隐私 ✓ 原版实测通过 macOS / Windows
📖 下面的示意图都是根据原版源码里的真实界面绘制的，不是凭空画的。所有文字（按钮名、气泡标题、状态提示）都取自真实界面，方便你对号入座。

先看整体：五个补丁各管一段

它们互不依赖——你完全可以只装其中一个。可以把 Uranus 想成一条"消息进来 → AI 生成 → 你看到结果"的链路，五个补丁分别守在不同位置：

01

常驻日志抽屉 + 模型快切

Log Drawer & Model Switch · 一眼看清是"在生成"还是"断了"，顺手把模型换掉
前端 + 1 个接口不改数据结构Mac / Windows随时可卸
痛点场景：线下模式等 AI 出字，页面一片空白干等——你分不清它是在"慢慢写"，还是 API 早就断了。想知道真相，只能切到「控制台」面板翻日志。等生成一趟回来，人已经走了。

还有一种：盯着日志发现某条线在拖后腿，想立刻换个模型——可换模型得跳去角色页、翻到对应角色、找到那一档、保存。等切完，戏都断了。

装了之后：角落永远钉着一颗小胶囊，实时显示链路是"连接中"还是"已断开"。点开就是完整日志面板，断网、限流、超时立刻冒红字——不用切页面。右上角还多一个 模型 按钮：选角色 → 选模型 → 切换，三个点击当场生效，聊天 / 线下 / 兜底都能切。

前端呈现

抽屉右上角还有一个 模型 按钮 —— 盯着日志发现哪条线不对，就地换掉：

怎么用

  1. 双击模块文件夹里的 安装.command：自动备份 → 复制组件 → 插 3 处锚点（前端 2 + 后端 1）→ npm run build → 重启 Uranus；任一步失败会自动回滚。
  2. 浏览器 Cmd+Shift+R 硬刷新，角落出现「运行日志」胶囊即成功。
  3. 点胶囊展开：上面是链路状态，下面是实时日志（级别筛选 / 搜索 / 暂停 / 清空）。断网、限流、超时立刻变红。
  4. 点右上角 模型：选角色（或「全部角色」）→ 选模型 → 选档位（聊天 / 线下 / 兜底）→ 点「切换」。右侧小字会变成「模型已切到 …」。
  5. 想撤销：双击同目录的 卸载还原.command，它会把 shell.jsx 和 index.js 还原成装之前的样子（实测字节一致）并重新构建。
原理与兼容性（点开）
日志为什么零后端
复用 Uranus 自带的 /api/logs/stream（SSE 日志流）——控制台面板本来就在用它。组件用 useLogs() 拿日志和连接状态，用控制台导出的 LogRow 渲染每一行，筛选/搜索/暂停全是组件内部的 useState。
模型快切为什么要加一个接口
原版保存配置走 PUT /api/config，要求前端先把整份配置发回去。抽屉是常驻的，手里那份可能已经是几小时前的——整包写回会盖掉你在别的面板里没保存的改动。所以新增 POST /api/role-model：后端自己 loadConfig() → 只改目标角色的 chatModel / offline.model / fallbackModel → saveConfig()，并且不刷桥接（模型引用是每轮现读的，刷桥接会把正在回话的连接掐掉）。
改了哪些文件
新增 client/src/logdrawer.jsx；client/src/shell.jsx 两处锚点后各插 1 行；server/src/index.js 在 app.get("/api/config/path") 前插入 1 个接口。没有改任何数据结构，改的都是角色卡原有字段。
为什么用"锚点插入"
shell.jsx / index.js 常被其他本地补丁改过，整文件替换会失败；锚点插入只认原版一定存在的几行，跟其他补丁互不打扰，重复运行也不会重复插入。
实测记录
在干净的原版 1.22.3 副本上装→卸往返验证：安装后 shell.jsx 含 LiveLogDrawer、index.js 含 /api/role-model；卸载后两个文件与基线逐字节一致。接口实测：批量改两个角色的「聊天+兜底」、单独改一个角色的「线下」均成功落盘；给一个被关闭的模型会返回 400「这个模型是关着的」，服务商不存在返回 404。
兼容性
只用上游已有的图标库、主题变量、日志 API 和 labels.js 导出的辅助函数，无新增依赖。Mac / Windows 源码完全相同，只是构建和重启命令不同。已在原版 1.22.x 上逐条验证锚点存在。
02

唤醒自愈（防断流）

Wake-up Self-heal · 睡醒后网络卡死，自动换掉
静默工作独立定时任务不改 Uranus 源码仅 macOS
痛点场景：Mac 睡一觉醒来，Uranus 看起来还活着（8787 在监听、进程也在），但网络栈被休眠挂死了——所有出网请求全超时（ENOTFOUND），iMessage 不回、IG 不动、主动发信不发。表现就是"隔天早上发现角色一夜没理我"。

装了之后：它完全静默。睡醒后若发现"进程比这次唤醒还旧"，等 90 秒冷静期，自动重启一次 Uranus，把卡死的网络栈换掉。日志平时是空的——空着就是正常。

它是怎么介入的（时间线示意）

怎么用

  1. 双击 install.command 安装。它只往 ~/Library/LaunchAgents 注册一个定时任务，不改 Uranus 任何源码。
  2. 验证：launchctl print gui/$(id -u)/com.uranus.wake-restart 有输出即在跑。
  3. 日志在 uranus-wake-restart.log，平时空着＝正常；真重启过才会写一行，附带上"进程启动时间早于最近唤醒、已唤醒多少秒"的原因。
  4. 不想要了，双击 uninstall.command——只删这个定时任务，不碰 Uranus 主服务。
原理与兼容性（点开）
判据（三条件同时）
① 8787 有进程监听（没有就交给 launchd 的 KeepAlive 自己拉，脚本不管）；② 进程启动时间早于最近一次"真正的唤醒"时间（取 pmset -g log，排除 DarkWake / Maintenance）；③ 已唤醒超过 90 秒（避开刚唤醒的网络抖动）。
为什么不用"杀进程重拨代理"的看门狗
那种做法曾导致两份看门狗互相 kill、代理每 15 秒重启一次的死循环。本补丁只调 launchctl kickstart（优雅重启），不 pkill，且判定严格、有冷静期，不误伤正常实例。
拿不到时间怎么办
进程启动时间用 ps lstart，拿不到回退 etime；两者都拿不到就保守跳过、不盲重启。
可调参数
脚本顶部 PORT=8787、URANUS_LABEL、WAKE_GRACE=90；检查频率在 plist 的 StartInterval（当前 120 秒）。
兼容性
仅 macOS（LaunchAgents / pmset / BSD 版 ps），全用系统自带命令，无需装任何东西。依赖 Uranus 由 launchd 托管、服务名 com.uranus.imessage（官方安装方式就是它）；手动 node 起的需把 kickstart 换成自己的启动方式。
注：关于检查频率
README 早期写"每 5 分钟"，实际 plist 为 120 秒（2 分钟）——以脚本为准，更灵敏但判定严格，不会因此频繁重启。
03

入站看门狗

Inbound Watchdog · "能发不能收"，自动重连
静默工作每 60 秒巡检需改服务端仅 macOS
痛点场景：Uranus 有时"半死"——发消息正常（对方看到已送达），但收消息彻底断了：控制台一条新消息都不进来，而 /api/health 还是 200、界面全绿，你根本看不出来。常见诱因是睡眠、切网、代理抖动后，收消息的长连接悄悄断了却没重建。

装了之后：每 60 秒巡检一次，发现收消息通道断了就自动重连（先重启桥接，不行再重启进程），并把过程写进日志。它也是静默的——修过才会写一行。

它是怎么发现"半死"的

怎么用

  1. 双击 安装.command：自动找 Uranus 目录、备份 server/src/index.js、加一个只收本机回环、只写一行日志的通知端点、装巡检脚本、注册每 60 秒的定时任务并重启 Uranus。
  2. 日志在 watchdog.log，平时空着＝正常，真修过才写一行。
  3. 配合模块 ① 使用时，左下角日志抽屉能实时看到 [看门狗] 行。
  4. 双击 卸载还原.command：停任务、还原服务端文件、重启 Uranus，不动你的角色和数据。
原理与兼容性（点开）
判据
只看日志、不需要登录态：比较"最后一次桥接已连接"和"最后一次订阅失败"的先后。失败在后＝连上后又崩了；连续 3 次巡检都这样才动手。
动作设计
先重启桥接（代价小），25 秒后还不行再重启整个进程；两次动手之间至少隔 10 分钟防抖。每 60 秒巡检，但动手有冷静期，刻意避开早年被验证会死循环的"代理不通就 pkill 重拨"方案。
改了哪些文件
服务端 server/src/index.js 加一个通知端点（仅限本机回环）；另在 patches/watchdog/ 装巡检脚本和 plist。安装前备份 index.js，随时可还原。
兼容性
原版可直接装（服务端补丁用官方锚点，已在原版验证命中）；macOS（launchd + pmset，系统自带命令）；需 Uranus 由 launchd 托管、服务名 com.uranus.imessage。
04

群像舞台

Cast Stage · 一场戏勾选出场，现场读单人卡，收工自动写记忆
原版可装需改服务端零硬编码与 01/05 共存
痛点场景：原版线下剧情一次只能演一个角色。想让几个人同场演一场戏？原版做不到。老办法是把几个人设硬塞进一张卡——改一个角色的人设，别的戏全受影响，串味、难维护。

装了之后：角色列表多一张「群像舞台」卡。开戏时勾本场哪几个角色出场，生成时现场读那些单人卡的人设——改任何单人卡，下一场自动读新版，不用重装、不用同步。每个人只照自己那份人设写，不串味。

前端呈现：从勾选到成戏

怎么用

  1. 双击 安装.command。装完 Cmd+R 强刷浏览器。
  2. 进「角色」→「群像舞台」：给它选一个聊天模型、一个线下模型（模板里模型槽位故意留空，不替你指定）。想让它读别人的记忆，就在 memoryShare.sources 里勾要读的角色库。
  3. 群像舞台 → 开启线下 → 开新剧情 → 勾本场出场角色（或开演后在主面板「本场出场」随时点选，下一轮生效）。
  4. 正常演 → 结束 → 自动写记忆。手机上也能用：剧情第一句写 【出场：角色A、角色B】（名字要和角色卡一致）。
原理与兼容性（点开）
现场读单人卡
生成时把出场者的单人卡 description 动态拼进提示词——改任何单人卡，下一场自动读新版，不用重装、不用同步。每个人只照自己那份人设写，不串味。
人称
配套装的原版改造预设把人称锁在"第二人称『你』只指读者、出场者一律用名字"，避免把几个人揉成一个人格。
收工写记忆
点「结束」后，按天合并落库，自动补一条群像大总结 + 给在场者各写一条 POV。日期按 Asia/Seoul；并发锁、幂等指纹防重复；只有点「结束」才触发，切换/关闭剧情不触发。
写在哪个库
群像集体库用 role-r-cast-stage（与舞台卡 id 对应）；在场者 POV 写进各自角色库，key 从角色卡现算。没出场的跳过。
改了哪些文件
服务端 13 处（出场名单存取、动态拼人设、收工触发）、前端 8 处（勾选 UI），另装舞台卡、基于原版出厂预设改造的通用群像预设、收工/扇出脚本。
兼容性 / 共存
原版 1.22.2 / 1.22.7 均实测可装（服务端 13 处、前端 8 处锚点全命中）。零硬编码：不写死角色名、称呼、模型、key。和模块 ⑤ 都改 offline.jsx 但锚点不同，已实测可同时装。

线下剧情增强

Offline Enhancing · 版本留底 / 气泡样式 / 模型token / 四钮跳转
原版可装四个功能一次装也可单装20 项自检
这一模块打包了四个小功能，都作用在线下剧情页：重 roll 之后旧稿没了？气泡配色手机电脑不一致？不知道这轮用的哪个模型、花了多少 token？翻长剧情全靠手滑？——一次全解决。

功能 ② 版本留底 · 旧稿能翻能恢复

功能 ③ 气泡样式 · 两侧配色分开调

功能 ④ 模型与 token · 气泡标题一眼看清

功能 ⑤ 四钮快速跳转 · 长剧情不用手滑

怎么用

  1. macOS 双击 安装.command，四个功能一次装好；想只装某一个，进 files 跑 node 安装器.mjs --only 05 --run（编号填 02/03/04/05）。
  2. 装完浏览器 Cmd+R 强刷，看到新按钮/新标题；服务端部分会提示重启 Uranus。
  3. 四个功能都在同一页线下剧情里：气泡上的「历史 N」、样式弹窗、气泡标题的用量、右缘四钮。
  4. 双击 卸载还原.command 用装前备份逐字节还原，只动这四功能改过的源码，不碰角色/记忆/剧情。
原理与兼容性（点开）
四个功能
02 版本留底：重 roll / 手改 / 删除的旧稿进 alts 存档，气泡「历史 N」可翻可恢复，恢复当前稿也先留底；旧稿不进上下文。03 气泡样式：两侧配色分开调，存服务端（跨设备同步），白名单字段 + 越界夹取。04 模型 token：识别 OpenAI / Gemini 原生 / Claude 三种用量格式，标题显示模型与 ↑输入(缓存)↓输出。05 四钮跳转：右缘四钮 + WebKit 回顶修复。
安全设计
装前备份到 .patches-backup-<时间戳>/；任一补丁对不上（版本差太多/文件被大改）就整份不写，不会改坏半个文件；装完自动跑 17–20 项自检，不联网、不碰真实数据。
版本与共存
按原版 1.22.3 源码做，1.22.2 / 1.22.7 实测也能打上。四功能改同一页 offline.jsx 不同段落，按 02→03→04→05 顺序叠加，安装器自动处理。和模块 ④ 群像舞台也改这个文件但锚点不同，已实测可同时装。

为什么可以放心用

零隐私：凡是需要"你是谁"的地方，都从你自己的 Uranus 读
