# 模块 4 · 群像舞台（勾选出场 · 读单人卡 · 自动写记忆）

## 解决什么

原版 Uranus 的线下剧情一次只能演一个角色。这个补丁让你**开一场戏时勾选本场哪几个角色出场**：

- 生成时**现场读那些单人卡的人设**（改任何单人卡，下一场群像自动读新版，不用重装、不用同步）
- 每个人只照自己那份人设写，不串味；台词用「名字：『台词』」
- 戏结束，**自动**按自然日切分，写一条群像大总结 + 给在场者各写一条**共享记忆**：一份全知第三人称总结原样写进每个在场角色库，逐字相同；未出场角色不写（按剧情指纹幂等，重跑不重复）
- 手机上也能用：剧情第一句写 `【出场：角色A、角色B】` 即可（名字要和你角色卡上的一致）

## 适配范围

- ✅ **原版 Uranus 1.22.x 可直接安装**——补丁锚点已用原版 1.22.2 源码逐条验证（服务端 13 处、前端 8 处全命中），并兼容 1.22.7 的写法
- ✅ 自带全部所需脚本，不依赖任何其他补丁
- ✅ 零硬编码：不写死任何角色名、称呼、模型、key——出场者从你自己的角色卡动态读取
- ✅ **macOS 与 Windows 都能装**：macOS 双击 `安装.command`，Windows 双击 `安装.bat`（同一份 Node 逻辑，只是重启方式不同）

## 装

把本文件夹放到任意位置，**双击 `安装.command`（macOS）或 `安装.bat`（Windows）**。脚本会：

1. 备份所有要改的文件到 `_备份/<时间>/`
2. 打服务端补丁（选角逻辑 + 收工触发 13 处）与前端补丁（勾选 UI 8 处）
3. 语法校验
4. 安装群像预设 `ps-3`——**基于 Uranus 原版出厂预设**做好的通用成品（61 条，不写死任何角色名、不碰你的原预设）。它把人称锁在「第二人称『你』只指读者、出场者一律用名字」，状态栏按本场出场者动态列出
5. 装「群像舞台」卡 + 收工/扇出脚本
6. 重新构建前端、重启 Uranus（macOS 用 `launchctl`；Windows 杀掉监听 8787 的 node 再重开启动器）

### 装完必做两件事

1. 浏览器强刷一次（macOS `Cmd+R` / Windows `Ctrl+F5`）
2. 进「角色」→「群像舞台」：给这张卡**选一个聊天模型、一个线下模型**（模板里模型槽位是空的，故意不替你指定）。想让它读别人的记忆，就在 `memoryShare.sources` 里勾你要读的角色库

## 用法

1. 角色「群像舞台」→ 开启线下 → 开启新剧情
2. 弹窗里勾本场出场角色；或开演后在主面板「本场出场」区随时点选（下一轮生效）
3. 正常演 → 结束 → 自动写群像大总结 + 在场者共享记忆（一份总结原样写进每个在场者库）
4. 改任何单人卡的人设，下一场自动读新版

## 撤销

双击 `卸载还原.command`（Windows：`卸载还原.bat`）：还原服务端/前端、移除舞台卡/预设/脚本、重建前端。
**你的角色卡、记忆库、剧情存档一字不删。**

## 关于「群像大总结/共享记忆」写进哪个库

- 群像集体记忆库固定用 `role-r-cast-stage`，与舞台卡 id 对应（架构约定）
- 一天生成一份**全知第三人称总结**（凡本场勾选出场的角色全程在场、全场细节共享，不写"他只看见"这种限知句），**原样**写进每个在场角色的记忆库——角色 A 和 B 那两条正文逐字相同
- 一场戏跨两天就切两份，各写各的日期，不会互相覆盖
- 幂等指纹 `cast:剧情id-日期.md-材料字数` 只认本剧情本日期；同一天别的戏不会误挡。重跑只补缺的人
- 只有勾选了出场的角色才会写；没出场的角色一个字都不写

## 常见问题

**Q：结束戏后没写记忆？**
A：看 Uranus 目录下的 `群像收工.log`。多半是没给舞台卡配模型，或模型空回——配一个稳定的模型即可，然后手动重跑：
`node patches/uranus群像收工.mjs --story <剧情id>`（幂等，可反复跑）。

**Q：和别的补丁冲突吗？**
A：只往官方锚点后插代码，且带同名标记防重复。升级 Uranus 后重跑一次安装脚本即可（它会提示已装 / 重装）。
